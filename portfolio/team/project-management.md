## Part 3: Project Management System

#### The Tools Stack
| Tool                | Purpose             | Cost      | Why I Use It                   |
| ------------------- | ------------------- | --------- | ------------------------------ |
| **GitHub Projects** | Task tracking       | Free      | Already in repo, Kanban boards |
| **Slack/Discord**   | Daily communication | Free      | Real-time, async-friendly      |
| **Loom**            | Video explanations  | Free tier | 5-min videos > 30-min meetings |
| **Notion**          | Documentation       | Free      | Wiki, SOPs, client docs        |
| **Toggl Track**     | Time tracking       | Free      | Contractor accountability      |

---
#### The GitHub Projects Workflow

##### Board columns:

1. Backlog — Ideas, future features, client requests
2. To Do — Assigned, not started
3. In Progress — Contractor working on it
4. In Review — PR open, awaiting review
5. Testing — Merged to staging, client testing
6. Done — Deployed to production

#### Issue template:
## Task: [Feature Name]

#### Context
[Why this matters. Link to client request or business goal.]

#### Requirements
- [ ] Requirement 1
- [ ] Requirement 2
- [ ] Requirement 3

#### Acceptance Criteria
- [ ] API responds correctly to [test case]
- [ ] Tests cover [scenarios]
- [ ] Documentation updated
- [ ] Client approves on staging

#### Estimated Effort
- [ ] Small (1-3 hours)
- [ ] Medium (4-8 hours)
- [ ] Large (9-16 hours)

##### Assigned to: @contractor-username
##### Due: [Date]
##### Client: [Client Name]

**Why this matters:** Every task has context, criteria, and a client. Contractors don't guess. You don't micromanage.

### The Weekly Rhythm
| Day           | Activity                      | Who                                   | Time       |
| ------------- | ----------------------------- | ------------------------------------- | ---------- |
| **Monday**    | Sprint planning (30 min)      | You + contractors                     | 30 min     |
| **Daily**     | Async standup in Slack        | Contractors                           | 5 min each |
| **Wednesday** | Mid-week check-in (15 min)    | You + contractors                     | 15 min     |
| **Friday**    | Sprint review + demo (30 min) | You + contractors + client (optional) | 30 min     |

#### Daily async standup (Slack):
```plain
@channel Standup thread — reply with:
1. What I completed yesterday
2. What I'm working on today
3. Any blockers or questions
```
**Why async:** Contractors work different hours. Respect their time. You review standups in 10 minutes, not a 30-minute meeting.
